## 1 绑定机制：Fact ↔ QML 属性的完整时序

### 1.1 元数据的三个来源与优先级

参数元数据不是从单一文件读取的，`CompInfoParam::_resolveMetaData` 决定实际来源（`src/Vehicle/ComponentInformation/CompInfoParam.cc:88-112`）：

| 来源 | 触发条件 | 实现位置 | 备注 |
|---|---|---|---|
| 车端下发 JSON（COMP_METADATA_TYPE_PARAMETER） | `_noJsonMetadata == false` | `CompInfoParam::setJson`（`src/Vehicle/ComponentInformation/CompInfoParam.cc:20-75`）、`_lookupJsonMetaData`（`:114-136`） | 支持 `{n}` 索引名模板，运行时按正则复制并替换短/长描述中的索引占位（`:117-132`） |
| 固件内置 JSON | 车端未提供 | `FirmwarePlugin::loadParameterMetaData`（`src/FirmwarePlugin/FirmwarePlugin.cc:523-540`）→ `ParameterMetaData::getMetaDataForFact`（`src/FirmwarePlugin/ParameterMetaData.cc:55-75`） | PX4 用 `:/FirmwarePlugin/PX4/PX4ParameterFactMetaData.json`（`src/FirmwarePlugin/PX4/PX4FirmwarePlugin.h:57`）；APM 用 `:/FirmwarePlugin/APM/APMParameterFactMetaData.<车型>.<主>.<次>.json`（`src/FirmwarePlugin/APM/APMFirmwarePlugin.cc:710-739`），该文件由 CMake 从 ArduPilot pdef 下载后以资源别名注入（`src/FirmwarePlugin/APM/CMakeLists.txt:67-101`），**仓库内不存在该文件本体** |
| 通用兜底 | 上述均查不到 | `CompInfoParam::_resolveMetaData`（`src/Vehicle/ComponentInformation/CompInfoParam.cc:102-111`） | `new FactMetaData(valueType)`；group 取参数名首个 `_` 前的前缀；非自驾仪组件（`compId != MAV_COMP_ID_AUTOPILOT1`）额外设 category = `Component <id>`（`:108-110`） |

解析链最末端还有一层按机型/固件的后处理：

- PX4：category 为空或等于默认值时强制改为 `"Standard"`；`volatile` 参数强制 `readOnly = true`；短/长描述中的换行替换为空格（`src/FirmwarePlugin/PX4/PX4ParameterMetaData.cc:59-78`）。
- APM：查不到元数据时 `_createDefaultMetaData` 设 category = `"Advanced"`、group = 参数名前缀（`src/FirmwarePlugin/APM/APMParameterMetaData.cc:204-210`）；名字以 `_P`/`_I`/`_D` 结尾的浮点参数强制 6 位小数（`:212-218`）。

### 1.2 一个 Fact 从报文到控件的时序

以下顺序对应"参数下载完成后，用户在参数页看到一行"的完整过程：

| 步骤 | 动作 | 位置 |
|---|---|---|
| 1 | 收到 `PARAM_VALUE`，解出名字/类型/值 | `ParameterManager::mavlinkMessageReceived`（`src/FactSystem/ParameterManager.cc:107-135`） |
| 2 | `_handleParamValue` 处理：类型由**报文的 MAV_PARAM_TYPE** 决定，而非元数据 JSON 的 `type` | `src/FactSystem/ParameterManager.cc:138`、`:250`（`mavTypeToFactType(mavParamType)`） |
| 3 | 首次遇到该参数：`new Fact(componentId, name, type)`。**Fact 构造函数先建立一份空 FactMetaData**，随后被真实元数据替换 | `src/FactSystem/ParameterManager.cc:250`；`src/FactSystem/Fact.cc:36-37` |
| 4 | `factMetaDataForName(parameterName, fact->type())` 取得元数据并 `setMetaData`。此处即"取元数据"时刻 | `src/FactSystem/ParameterManager.cc:251-252`；`src/Vehicle/ComponentInformation/CompInfoParam.cc:77-86` |
| 5 | 发出 `factAdded(componentId, fact)`，参数页据此增量插入行 | `src/FactSystem/ParameterManager.cc:259`；信号声明 `src/FactSystem/ParameterManager.h:134` |
| 6 | `fact->containerSetRawValue(parameterValue)` 写入值，并发出 `valueChanged` 与 `vehicleUpdated` | `src/FactSystem/ParameterManager.cc:262`；`src/FactSystem/Fact.cc:198-224` |
| 7 | 参数页控制器构造时先 `_buildLists()` 全量建表；之后再通过 `_factAdded` 增量补齐 | `src/QmlControls/ParameterEditorController.cc:159`、`:171`、`:275-338` |
| 8 | QML 表格模型指向 `controller.parameters`，模型变化即触发渲染 | `src/QmlControls/ParameterEditor.qml:334` |

**关键结论（由源码推断，未实机验证）**：Fact 对象在收到第一个 `PARAM_VALUE` 时创建，元数据在同一步内挂接（步骤 3→4 之间无异步等待），因此 QML 首次渲染到某一行时其元数据已经就绪，不存在"先渲染后补元数据"的空窗。反之，页面级 `controller.getParameterFact(...)` 取得的是**已在下载阶段构造好的 Fact 引用**（`src/FactSystem/FactControls/FactPanelController.cc:57-70`），所以 Setup 页必须在参数下载完成后才有意义——这正是 `VehicleConfigView.qml` 用 `parameterReadyVehicleAvailable && !missingParameters` 作为可用前提的原因（`src/Vehicle/VehicleSetup/VehicleConfigView.qml:31`）。

## 2 分组、搜索与排序

### 2.1 分组：category 一级、group 二级

参数页左栏是"分类 → 组"两级结构，数据模型为 `ParameterEditorCategory`（含 `groups`）与 `ParameterEditorGroup`（含 `facts` 表模型），声明于 `src/QmlControls/ParameterEditorController.h:61-93`。构建逻辑在 `_buildListsForComponent`（`src/QmlControls/ParameterEditorController.cc:184-216`）：

1. 遍历该组件全部参数名（`_parameterMgr->parameterNames(compId)`，`:186`）；
2. 用 `fact->category()` 查/建一级分类（`:194-201`）；
3. 在该分类内用 `fact->group()` 查/建二级组（`:204-212`）；
4. 把 Fact 追加到该组的 `ParameterTableModel`（`:214`）。

QML 侧用两层 `Repeater` 渲染：外层 `model: controller.categories`、内层 `model: categoryHeader.checked ? object.groups : 0`（`src/QmlControls/ParameterEditor.qml:222-260`）。

### 2.2 排序规则（含实现与已知偏差）

| 规则 | 实现位置 | 说明 |
|---|---|---|
| 自驾仪组件（`MAV_COMP_ID_AUTOPILOT1`）优先构建 | `src/QmlControls/ParameterEditorController.cc:228`、`:253-257` | 其它组件在其后追加 |
| `"Standard"` 分类置顶 | `:231-238` | 只在自驾仪组件的分类集合内调整 |
| 默认分类 `"Other"` 置底 | `:241-250` | 常量见 `src/FactSystem/FactMetaData.h:241` |
| 默认组 `"Misc"` 置底 | `:260-272` | 常量见 `src/FactSystem/FactMetaData.h:242` |
| 增量新增的分类按名称升序插入 | `:291-302` | 后续到达的参数触发 |
| 增量新增的组按名称升序插入 | `:314-327` | |
| 组内 Fact 按参数名升序插入 | `:330-337` | 通过 `facts.factAt(i)->name() > fact->name()` 比较 |
| 初次全量构建时组内顺序 = `parameterNames()` 返回顺序 | `src/FactSystem/ParameterManager.cc:839-850` | 底层 `QMap<QString, Fact*>`，`keys()` 即字典序 |

**两处需注意的偏差（由源码推断，未实机验证）**：

- `"Other"` 置底只发生在"其它组件尚未加入"之前（`:241-250` 早于 `:252-257`），因此当存在非自驾仪组件时，`"Other"` 实际不在最末位，与注释"Default category should always be last"不一致。
- `"Misc"` 组的置底判断写作 `if (j != _categories.count() - 1)`（`:265`），其中 `j` 是**组在分类内的下标**，却与**分类总数**比较；按上下文应为 `category->groups.count() - 1`。当分类数与组数不等时，`"Misc"` 无法被移到末尾。

### 2.3 搜索：匹配哪些字段

- 触发与去抖：搜索框 `onDisplayTextChanged` 写入 `controller.searchText`（`src/QmlControls/ParameterEditor.qml:155-159`），控制器用 300 ms 单次定时器去抖后执行 `_performSearch`（`src/QmlControls/ParameterEditorController.cc:161-162`、`:669-672`、`:170`）。
- 分词与语义：按空格切分（`:691`），**所有词都必须命中**（AND 语义，`:712-731`）；单个词按 `QRegularExpression` 大小写不敏感匹配，正则非法时退化为 `QString::contains(..., Qt::CaseInsensitive)`（`:698-729`）。
- 命中字段：`fact->name()`、`fact->shortDescription()`、`fact->longDescription()`（`:717-727`）。
- **不匹配枚举文本 / 位掩码文本**：`enumStrings`、`bitmaskStrings` 未参与匹配。因此按枚举显示文本（如 "Yaw 90°"）检索不到对应参数——这是与任务预设不同的事实，需在二次开发中作为改进点记录。
- 搜索期间侧栏分组被隐藏（`_searchFilter`，`src/QmlControls/ParameterEditor.qml:16`、`:214`），表格左边界改贴父容器（`:330`）。
- 过滤条件与搜索共用同一路径：`Hide read-only`（`src/QmlControls/ParameterEditorController.cc:189-191`、`:653-655`）、`Modified` 页签（`:656-660`）、`Favorites` 页签（`:661-665`），三者任一为真即进入"搜索结果"模式（`src/QmlControls/ParameterEditor.qml:16`、`:193-200`）。
- 收藏持久化：读写 AppSettings 的 `favoriteParameters`（`:824-837`）。
- 另有独立的一条搜索路径用于配置页侧栏：匹配组件名、section ID、译文名与 JSON `keywords`（`src/Vehicle/VehicleSetup/VehicleConfigView.qml:84-130`，关键词来源 `src/AutoPilotPlugins/VehicleComponent.cc:66-70`、`:175-229`）。

## 3 类型 → 控件映射表

QGC 中**不存在一个统一的"按 FactMetaData.type 运行时分发控件"的组件**。实际存在三条并行路径，必须分别说明。

### 3.1 路径 A：手写参数页（运行时按 fact 属性分支）

手写页面的控件由 QML 作者显式选择；类型分支只出现在少数"通用渲染器"里。已确认的分支实现：

- `ActuatorFact.qml`（目录 `src/AutoPilotPlugins/PX4/`）：按 `enumStrings.length > 0` → 下拉；否则 `readOnly` → 纯文本标签；否则 `typeIsBool` → 复选框；否则文本框（`src/AutoPilotPlugins/PX4/ActuatorFact.qml:48-51`）；fact 为空渲染 `(Param not available)`（`:42-47`）。
- `ParameterEditorDialog.qml`（目录 `src/QmlControls/`）：`_showCombo = fact.enumStrings.length !== 0 && fact.bitmaskStrings.length === 0`（`:25`）；位掩码列 `visible: fact.bitmaskStrings.length > 0 && !_readOnlyDisplay`（`:154`）。
- `FactComboBox.qml`（目录 `src/FactSystem/FactControls/`）：`indexModel = fact.enumValues.length === 0`，即元数据无枚举值时把"Fact 值本身"当作下标使用（`:9`、`:13`、`:37-43`）。
- `FactCheckBox.qml`（同目录）：`typeIsBool` 时用布尔语义，否则用 `value !== 0`（`:13-21`）。

## 4 单位与显示转换

### 4.1 双域模型

- raw 值 = 车端值；cooked 值 = `rawTranslator(rawValue)`（`src/FactSystem/Fact.cc:226-235`）。
- `Fact.valueString` 返回**cooked 值**按 `decimalPlaces` 格式化（`src/FactSystem/Fact.cc:488-491`）；`Fact.units` 返回 `cookedUnits()`（`src/FactSystem/Fact.h:52`、`src/FactSystem/Fact.cc:571-579`）。
- 控件写值时有两条入口：`fact.value = <cooked>` 走 `setCookedValue`（先 `cookedTranslator` 转回 raw，`src/FactSystem/Fact.cc:163-170`）；`fact.rawValue = <raw>` 直接写原始域（生成页的 `combobox`/`radiogroup raw:true` 用这条，`control_combo_enum.qml.j2:9`、`controls.py:428`）。

### 4.2 换算表如何选定

`FactMetaData::setRawUnits` 会立即调用 `setBuiltInTranslator`（`src/FactSystem/FactMetaData.cc:862-868`）：

1. 若该参数有 `enumStrings` 或 `bitmaskStrings` → **不做任何换算**，`cookedUnits = rawUnits`（`:647-651`）；
2. 否则查内置换算表 `_rgBuiltInTranslations`（`src/FactSystem/FactMetaData.cc:21-28`）：`centi-degrees→deg`、`radians/rad→deg`、`gimbal-degrees→deg`、`norm→%`、`centi-celsius→C`；
3. 未命中则查受应用设置驱动的表 `_rgAppSettingsTranslations`（`:31-60`），按 `UnitsSettings` 中该类单位的选择项匹配，例如 `m→ft`、`m/s→km/h|mph|kn|ft/s`、`C→F`、`g→kg|oz|lbs`、`m^2→ha|km^2|ft^2|ac|mi^2`；
4. 特殊：人工单位 `"vertical m"` 在未命中时会被改写成 `"m"`，避免暴露给用户（`:966-970`）。

因此"用户改单位设置"会改变 cooked 域数值与单位文字，而这些设置本身被标记为需要重启应用（`src/Settings/UnitsSettings.cc:33,64,101,137,168,202` 均调用 `setQGCRebootRequired(true)`）。

### 4.3 小数位如何确定

`FactMetaData::decimalPlaces()`（`src/FactSystem/FactMetaData.cc:1166-1206`）按优先级：

1. 元数据显式给出 `decimalPlaces` → 直接采用（`:1201-1203`）；
2. 否则若 `increment` 有效 → 取其小数部分 `frac`，`frac == 0` 时为 0 位，否则 `-ceil(log10(frac))`（`:1172-1184`）；
3. 否则回退 `kDefaultDecimalPlaces = 3`，并按 cooked 换算比例补偿 `-log10(rawTranslator(1.0))`，最终夹在 `[0, 25]`（`:1190-1199`；常量见 `src/FactSystem/FactMetaData.h:231`）。

例外：APM 的 `_P/_I/_D` 浮点强制 6 位（`src/FirmwarePlugin/APM/APMParameterMetaData.cc:212-218`）；生成器也可用 JSON 的 `decimalPlaces` 覆盖 `FactSlider` 的位数（`tools/generators/common/controls.py:690-691`）。

### 4.4 单位在控件上的落点

| 控件 | 单位显示方式 | 位置 |
|---|---|---|

## 5 阈值与告警（min/max 越界如何呈现）

### 5.1 校验发生在哪里

- 校验的唯一入口是 `FactMetaData::convertAndValidateCooked`（`src/FactSystem/FactMetaData.cc:437-526`）与 `convertAndValidateRaw`（`:356-435`）。越界文案统一为 `"Value must be within %1 and %2"`（例如 `:457`、`:475`、`:491`、`:500`）；类型转换失败追加 `"Invalid number"`（`:521-523`）；字符串超长给出 `"Value must be %1 characters or less"`（`:507-509`）。
- `convertOnly == true` 时**只做类型转换、不做范围校验**（`:455`、`:473` 等分支的 `!convertOnly` 条件）。

### 5.2 输入框路径：先报错、不写值

`FactTextField._onEditingFinished`（`src/FactSystem/FactControls/FactTextField.qml:23-32`）：

1. `fact.validate(text, false)`；
2. 返回空串 → `clearValidationError()` 后写值；
3. 返回错误串 → `showValidationError(errorString, fact.valueString)`，**不写值**（非法值不会被提交到 Fact）。

`showValidationError` 的视觉与交互后果（`src/QmlControls/QGCTextField.qml:62-83`、`:85-92`、`:150-164`）：

- 输入框边框变为红色且加粗（`border.color: validationError ? qgcPal.colorRed : ...`，`border.width: 2`）；
- 弹出 ToolTip 承载错误文本；
- ToolTip 内点击可把文本恢复为出错前的合法值（`control.text = validationToolTip.originalValidValue`，`:158-161`）；
- 全局 `globals.validationErrorCount++`，进而**阻止界面切换**：`MainWindow.allowViewSwitch()` 在切换视图前会强制对当前聚焦的 `FactTextField` 调用 `_onEditingFinished()`，并弹出 `Please correct the invalid value before continuing`（`src/MainWindow/MainWindow.qml:122-132`、`:385-398`）。

因此答案是：**允许在输入框里键入非法值，但非法值不会生效，且会阻止离开当前页面**。

### 5.3 单参数对话框路径：区分"校验失败"与"强制保存"

`ParameterEditorDialog.onAccepted`（`src/QmlControls/ParameterEditorDialog.qml:35-55`）：校验失败时把错误文本写入对话框内的 `validationError` 标签（红色 `qgcPal.warningText`，`:86-92`）并设 `preventClose = true`，对话框不关闭。仅当 `_allowForceSave == true`（即 `corePlugin.showAdvancedUI && fact.componentId != 0`，`:23`）时才显示 `Force save (dangerous!)` 复选框（`:49-51`、`:224-228`）；勾选后以 `convertOnly = true` 重新校验（`:43`），从而绕过范围校验但保留类型校验。

### 5.4 边界值的显示与滑块硬限制

- 对话框只在 min/max **不是该类型的默认极值**时才显示 `Min:` / `Max:` 标签（`visible: !fact.minIsDefaultForType` / `!fact.maxIsDefaultForType`，`:189-198`；判定见 `src/FactSystem/FactMetaData.h:136,139`）。
- 滑块类控件把边界做成硬约束，越界即被夹紧：
  - `ValueSlider._clampedSliderValue` → `Math.min(Math.max(value, from), to).toFixed(decimalPlaces)`（`src/QmlControls/ValueSlider.qml:129-131`）；
  - `FactTextFieldSlider.updateSliderToClampedValue` 在 fact 值超出 slider 量程时把滑块位置夹到量程内（`src/FactSystem/FactControls/FactTextFieldSlider.qml:42-52`）；
  - `FactTextFieldSlider2` 的 ± 按钮用 `Math.max(Math.min(...))` 夹紧（`src/FactSystem/FactControls/FactTextFieldSlider2.qml:86,95`）；
  - `LabelledFactIncrementer` 在到达 `.min`/`.max` 时停止步进（`src/FactSystem/FactControls/LabelledFactIncrementer.qml:38,55`）。
- `FactSlider` 在量程退化为类型极值时打印错误日志提示元数据缺失（`src/QmlControls/FactSlider.qml:25-30`）。
- 注意：`Fact::setCookedValue`/`setRawValue` 内部以 `convertOnly = true` 调用校验（`src/FactSystem/Fact.cc:140`、`:166`），**因此程序化赋值（含滑块拖拽、生成页 radiogroup）不会因越界而被拒绝**；范围约束只体现在 QML 控件的输入校验与夹紧上。`Fact::clamp()` 存在但当前 QML 侧未见调用（`src/FactSystem/Fact.h:84`，`grep '\.clamp('` 在 `src/**/*.qml` 无命中）——此结论由源码推断，未实机验证。
- 与阈值相关的业务告警色示例：APM 安全页在 arming check 被修改时以 `qgcPal.warningText` 显示"关闭检查可能导致失控"（`src/AutoPilotPlugins/APM/APMFlightSafetyComponentSub.qml:241-246`）；生成式页面用 `label + warning:true` 表达同一效果（`src/AutoPilotPlugins/APM/VehicleConfig/APMFlightSafety.VehicleConfig.json:354-358`）。

## 6 reboot 提示与参数写入的状态反馈

### 6.1 reboot required

- `rebootRequired` 的两条来源：JSON 键 `rebootRequired`（`src/FactSystem/FactMetaData.cc:1429-1433`，键名常量 `src/FactSystem/FactMetaData.h:466`）；APM pdef 的 `RebootRequired` 字段（`src/FirmwarePlugin/APM/APMParameterMetaData.cc:110-112`）。`qgcRebootRequired` 只从 JSON 键 `qgcRebootRequired` 读取（`src/FactSystem/FactMetaData.cc:1423-1427`），仓库内由 `src/Settings/UnitsSettings.cc` 等设置项使用。
- 事前提示（静态）：单参数对话框底部按事实显示 `Vehicle reboot required after change` / `Application restart required after change`（`src/QmlControls/ParameterEditorDialog.qml:206-214`）。
- 事后提示（写入瞬间）：`Fact::_checkForRebootMessaging` 由 `containerRawValueChanged` 触发，调用 `QGC::showRebootVehicleMessage` 或 `QGC::showRebootAppMessage`（`src/FactSystem/Fact.cc:81-84`、`:934-944`；封装 `src/Utilities/AppMessages.cc:23-34`）。
- 提示形式与去抖：Vehicle 版会弹带"重启载具"按钮的对话框（`src/QGCApplication.cc:481-507`）；两类提示共用 2 分钟去抖（`_rebootMessageDebounced`，`:468-470`）。
- 需注意触发条件：`containerRawValueChanged` 在**本地写入**与**车端回读**（`containerSetRawValue`）时都会发出（`src/FactSystem/Fact.cc:154`、`:202`），因此单参数改动可能触发多次提示，仅靠去抖抑制。另有代码显式规避误提示：参数文件比对时临时关闭 `vehicleRebootRequired`（`src/QmlControls/ParameterEditorController.cc:522-527`）。此行为由源码推断，未实机验证。

### 6.2 写入链路与状态反馈

写入由 `ParameterManager::_mavlinkParamSet` 的 `QGCStateMachine` 驱动（`src/FactSystem/ParameterManager.cc:306-464`），流程与反馈如下：

| 阶段 | 机制 | 用户可见反馈 | 位置 |
|---|---|---|---|
| 触发 | `Fact::containerRawValueChanged` → `_factRawValueUpdated` → `_mavlinkParamSet` | 无 | `src/FactSystem/ParameterManager.cc:536-545` |
| 发送 | 发 `PARAM_SET`，最多重试 `kParamSetRetryCount = 2` 次 | 无 | `:398`；常量 `src/FactSystem/ParameterManager.h:111` |
| 写入中计数 | `_pendingWritesCount++` 并发出 `pendingWritesChanged` | **界面上无逐参数进行中指示**；仅暴露 `pendingWrites` 属性 | `:1928-1936`；属性 `src/FactSystem/ParameterManager.h:28` |
| 等待 ack | 等 `PARAM_VALUE` 回读或 `PARAM_ERROR`，超时 `kWaitForParamValueAckMs = 1000`（测试 50 ms） | 无 | `:411`；常量 `src/FactSystem/ParameterManager.h:113,238` |
| 成功 | 写日志 + 发内部信号 `_paramSetSuccess` | **无 UI 反馈**（不弹提示、不变色），成功是"静默"的 | `:428-431` |
| 失败 | 发 `_paramSetFailure`，随后 `QGC::showAppMessage("Parameter write failed: param: ...")`，并主动回读该参数以恢复 UI 显示 | 全局消息条（应用消息） | `:421-435`；`:412-420`；消息封装 `src/Utilities/AppMessages.cc` |
| 计数归零 | `_pendingWritesCount--`，归零时 `pendingWritesChanged(false)` | 仅用于关闭程序时的二次确认 | `:1938-1947`；`src/MainWindow/MainWindow.qml:280-295` |
| 车端回读 | `Fact::containerSetRawValue` 发 `vehicleUpdated` | 控件值随之刷新 | `src/FactSystem/Fact.cc:198-224` |

补充事实：

- `Fact::vehicleUpdated` 是 C++ 侧等待"写入确实到车"的钩子，例如机身框架切换后等 `SYS_AUTOSTART`/`SYS_AUTOCONFIG` 落盘再重启（`src/AutoPilotPlugins/PX4/AirframeComponentController.cc:85-88`）、RC-to-Param 调参（`src/QmlControls/RCToParamDialogController.cc:45`），但 **QML 控件未订阅该信号**（`grep vehicleUpdated` 在 `src/**/*.qml` 无命中）。

- 参数下载进度另有独立 UI：工具栏底部进度条（`src/Toolbar/ParameterDownloadProgress.qml:15-21`，宽度 = `loadProgress * width`）。

### 7.4 枚举/位掩码文本缺失

- 当前值不在枚举表内时，`Fact::enumIndex()` 会**动态追加**一项 `tr("Unknown: %1").arg(rawValue)` 到元数据的枚举表中，并用 `Qt::QueuedConnection` 补发 `enumsChanged`（避免在 QML 绑定读取过程中同步发信号造成绑定环）（`src/FactSystem/Fact.cc:281-286`）。因此下拉框会多出一项形如 `Unknown: 7`，且该项会一直留在该参数的枚举表里。
- 正因如此，`ParameterEditorDialog.qml` 在初始化下拉框时特意不直接绑定 `fact.enumIndex`，改为 `Component.onCompleted` 中赋值，并注明"直接绑定会在没有枚举文本时额外加入一个未知值"（`src/QmlControls/ParameterEditorDialog.qml:119-125`）；`FactComboBox.qml` 同样在 `onModelChanged` 里用 `Qt.callLater` 重建绑定（`src/FactSystem/FactControls/FactComboBox.qml:15-35`）。
- 位掩码一位都没命中时，`Fact::selectedBitmaskStrings()` 返回单元素列表 `"Not value selected"`（上游原文如此，含语法瑕疵）（`src/FactSystem/Fact.cc:360-362`）。该字符串会直接出现在参数页值列，因为值列逻辑是 `fact.selectedBitmaskStrings.join(',')`（`src/QmlControls/ParameterEditor.qml:437-439`）。
- 位掩码数组与文本数组长度不一致时返回空列表并打警告（`src/FactSystem/Fact.cc:348-351`）。

### 7.5 参数不存在

- `ParameterManager::getParameter` 找不到时返回成员 `_defaultFact` 并调用 `qgcApp()->reportMissingParameter`（`src/FactSystem/ParameterManager.cc:826-837`）。
- 缺失参数被聚合，并在一段时间后以全局消息弹出：`"Parameters are missing from firmware. ... Missing params: <compid>:<name>, ..."`（`src/QGCApplication.cc:370-399`）。
- Setup 页取得 Fact 的两条路径：`getParameterFact(componentId, name)` 缺失时返回 `nullptr` 并上报（`src/FactSystem/FactControls/FactPanelController.cc:57-70`）；显式传入 `false` 则不报缺失，由 QML 自行处理 null（如 `src/AutoPilotPlugins/APM/APMFlightSafetyComponentSub.qml:27,46-47`）。
- 生成式页面的 `optional` 语义即由此而来：`optional:true` → `getParameterFact(-1, name, false)`（`tools/generators/config_qml/control_renderers.py:43-45`），并自动附加 `visible: <fact> !== null`（`tools/generators/config_qml/model.py:130-140`：`fact_guard = f"{fact_ref} !== null" if optional and param else ""`，与显式 `showWhen` 以 `&&` 组合）。

### 7.6 其它降级

- 参数下载未完成/被跳过/不完整时，配置页整体降级为提示文本，并提供 `Download Parameters` 按钮（`src/Vehicle/VehicleSetup/VehicleConfigView.qml:281-329`）。
- 数值为 NaN（无效）时按类型输出占位符：浮点 `–` 或 `–.––`（位数决定），时长 `––:––:––`，其它 `–`（`src/FactSystem/Fact.cc:429-443`，调用点 `:386-419`）；负零被剥离（`:375-381`）。
- 空 Fact 兜底模式：FactControls 中大量控件声明 `property Fact fact: Fact { }`，未赋值时给出一个类型为 Int32 的空 Fact，避免属性解引用崩溃（例如 `src/FactSystem/FactControls/FactComboBox.qml:8`、`FactCheckBox.qml:8`、`FactBitmask.qml:13`）；`FactSlider.qml` 另设 `_nullFact` 并用 `_fact` 统一取值（`src/QmlControls/FactSlider.qml:18-19`）。

## 9 面向"改善前端可用性"的观察清单

以下条目均为**由源码推断，未实机验证**，按证据强度列出，供二次开发选题：

1. **写入成功无反馈**：成功路径只写日志并发出 `_paramSetSuccess`，QML 无订阅（`src/FactSystem/ParameterManager.cc:428-431`；`src/**/*.qml` 无 `vehicleUpdated`/`_paramSetSuccess` 引用）。用户唯一能感知的是控件值变化，失败时才弹全局消息。
2. **无逐参数"写入中"指示**：`pendingWrites` 只用于退出确认（`src/FactSystem/ParameterManager.h:28`、`src/MainWindow/MainWindow.qml:280-295`）。
3. **搜索不含枚举/位掩码文本**：`src/QmlControls/ParameterEditorController.cc:717-727` 仅匹配 name / shortDesc / longDesc。
4. **生成式配置页 `control` 缺省为文本框**，与生成器 README 声称的"自动推断"不符（`tools/generators/config_qml/control_renderers.py:374` vs `tools/generators/config_qml/README.md:95-96`）。
5. **分组排序两处偏差**：`Other` 分类在存在多组件时不置底、`Misc` 组置底判断用错计数（`src/QmlControls/ParameterEditorController.cc:241-250`、`:265`）。
6. **参数表提示信息有限**：第 4 列固定为 `shortDescription`（`src/QmlControls/ParameterEditorController.cc:102`），长描述、单位、min/max 均需打开对话框才能看到（`src/QmlControls/ParameterEditorDialog.qml:178-204`）。
7. **只读与"无控件"语义分离**：`hasControl` 与 `readOnly` 是两个字段，QML 侧对 `hasControl` 的使用很少（`src/FactSystem/FactMetaData.h:152-153`）。
8. **枚举未知值会污染元数据表**：`Fact::enumIndex()` 会把 `Unknown: <值>` 永久追加进该参数的 `enumStrings`（`src/FactSystem/Fact.cc:281-286`），对枚举下拉框与列表显示均有副作用。
9. **reboot 提示可能重复触发**：本地写值与车端回读都走 `containerRawValueChanged`，仅靠 2 分钟去抖抑制（`src/FactSystem/Fact.cc:154`、`:202`、`:934-944`；`src/QGCApplication.cc:468-470`）。
10. **位掩码未选中文案为上游原文 `Not value selected`**，语法不完整，会直接暴露在参数表值列（`src/FactSystem/Fact.cc:361`；`src/QmlControls/ParameterEditor.qml:438`）。
