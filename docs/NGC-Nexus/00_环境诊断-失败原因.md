# NGC-Nexus 环境诊断：本机失败点全记录

记录时间：2026-09-25　环境：Windows / DSH 会话（file policy = workspace-write）　Shell：Windows PowerShell 5.1

本文件记录本次任务执行过程中**实际发生的每一类失败**，含根因与已验证的修复方式。所有结论均为本机实测，非推测。

---

## 失败点 1：`git` 无法访问 GitHub（schannel TLS 后端）

### 现象

```
fatal: unable to access 'https://github.com/mavlink/qgroundcontrol.git/':
schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)
- 安全程序包没有可用的凭证
```

### 根因

Git for Windows 默认 TLS 后端是 **schannel**（调用 Windows SChannel/SSPI）。
受限令牌下 SChannel 拿不到可用凭证句柄，于是**在发出任何 HTTP 请求之前就失败**——与网络、代理、GitHub 可达性完全无关。

### 证据（对照实验）

| 后端 | 命令 | 结果 |
|---|---|---|
| schannel（默认） | `git ls-remote https://github.com/mavlink/qgroundcontrol.git HEAD` | ❌ `SEC_E_NO_CREDENTIALS` |
| openssl | `git -c http.sslBackend=openssl ls-remote ... HEAD` | ✅ 返回 `25185047e8...` |

### 修复

仓库级（**不动全局配置**）：

```powershell
git -C <repo> config http.sslBackend openssl
```

Git for Windows 自带 CA 包确认存在：`C:\Program Files\Git\mingw64\etc\ssl\certs\ca-bundle.crt`。
代理由既有全局配置提供：`http.proxy = http://127.0.0.1:7897`（本次未改动）。

## 失败点 2：写全局 `.gitconfig` 被拒

### 现象

```
error: could not lock config file C:/Users/Marx/.gitconfig: Permission denied
```

### 根因

file policy 为 **workspace-write**：只允许写 `E:\04-Workspace_workbudy` 及其子目录。
`C:\Users\Marx\` 在工作区之外 → 写操作被沙箱拒绝。

### 修复

改用**仓库级配置**（`git config --local`）或命令行 `-c` 一次性传入。本次未申请提权，因为仓库级配置已足够。

## 失败点 3：`pwsh` 命令不存在（后台任务 exit 1）

### 现象

```
pwsh : The term 'pwsh' is not recognized as the name of a cmdlet, function, script file, or operable program.
[status: completed, exit code: 1]
```

### 根因

本机只装 **Windows PowerShell 5.1**，没有 PowerShell 7：

- `$PSVersionTable.PSVersion` = `5.1.26100.9444`，`PSEdition` = `Desktop`
- `Get-Command pwsh` → 空；`Get-Command powershell` → `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`

外壳本身以 5.1 启动（工具名虽写作 `pwsh -Command`），命令里再调 `pwsh` 必然找不到。

### 修复

用 5.1 兼容写法调用脚本，不嵌套 `pwsh`：`& '.\script.ps1' *>&1 | Tee-Object -FilePath <绝对路径>`

## 失败点 4（假故障，澄清）：`gh repo list` 输出空表

### 现象

`gh repo list Whale-Talk --json ... | ConvertFrom-Json | Select-Object ... | Format-Table` 输出只有表头的空表。

### 根因

`gh` 侧**没有失败**：原始 JSON 可见 8 个仓库（oh-my-deepseek、causal-alpha-lab、PX4-Autopilot-mjy、TEAMmanagementSYS、TencentDB-Agent-Memory、Nexus-Code、backtest-mcp、ClaudeCode）；`gh api user` 正常返回 `login=Whale-Talk`。
问题在我的 PowerShell 5.1 管道/显示写法，把对象渲染丢了。

### 修复

不依赖 `Format-Table` 渲染，直接用 `gh ... --jq` 输出纯文本。

## 失败点 5：`gh 2.96` 不支持 `--add-topic`

### 现象

```
gh : unknown flag: --add-topic
```

### 根因

本机 `gh` 版本为 **2.96.0**，`gh repo create` 没有 `--add-topic` 标志（该能力属较新版本）。

### 修复

`gh repo create` 只用 `--public --description`；topics 另用 API 设置：

```powershell
gh api -X PUT repos/<owner>/<repo>/topics -f 'names[]=a' -f 'names[]=b' ...
```

**注意**：`PUT /topics` 是**整体替换**语义——分多次单 topic 调用会互相覆盖（实测最后一次生效，只剩 1 个 topic）。必须一次调用传全部。

## 失败点 6：沙箱禁止子进程创建命名管道 → `sh.exe`/`bash.exe` 无法启动

### 现象

```
sh.exe: *** fatal error - couldn't create signal pipe, Win32 error 5
```

退出码 `-1073741502`（`STATUS_DLL_INIT_FAILED`）。对照实验：`sh.exe -c "echo hi"` 与 `bash.exe -c "echo hi"` **均直接失败**。

### 三条连带影响（本次全部遇到）

| 影响 | 表现 | 处理 |
|---|---|---|
| `git submodule` 不可用 | `git clone --recursive` / `submodule status` 均 exit 66 | QGC 上游**无 `.gitmodules`**，源码树自包含，实际无影响 |
| git `credential.helper` 失效 | `error: failed to execute prompt script (exit code 66)`、`could not read Username for 'https://github.com'` | 改用原生 exe 助手 `gh auth git-credential`（已验证可取到 `username=Whale-Talk`），或直接注入 token URL |
| git push 期间 `sh.exe` 报错 | 传输过程中打印 fatal error（**不致命**，推送仍成功） | 视为噪声，以最终 exit code 与远端校验为准 |

### 修复

凭证不再依赖 shell 实现：`git -c credential.helper='!gh auth git-credential' push ...`，或 `https://x-access-token:<token>@github.com/...`（token 仅用于网络请求，不落盘、输出中做掩码）。

## 失败点 7：浅克隆导致 push 被远端拒绝（**本次最关键的失误**）

### 现象

```
remote: fatal: did not receive expected object 3ae7a91544d0387f1fcb8fb65efcaf1b71cab6d3
error: remote unpack failed: index-pack failed
 ! [remote rejected] master -> main (failed)
```

### 诊断过程与排除项

1. **不是鉴权**：报错是 `remote rejected` 而非认证失败，凭证已生效。
2. **不是沙箱**：申请更宽 file policy 后**报错完全不变**，证明与权限无关。
3. **不是网络**：远端明确回话"没收到期望的对象"，说明连接与上传均已完成到校验阶段。
4. **真正根因**：`git clone --depth 1` 只含 **1 个提交**且带 shallow 边界（`.git/shallow` 存在），该仓库对象图不完整，push 时远端 `index-pack` 校验失败。

### 修复

```powershell
git -C <repo> -c http.sslBackend=openssl fetch --unshallow <upstream-url> master
```

实测一次通过：提交数 1 → **21945**，`.git/shallow` 被移除，随后 push 成功。

### 附带教训

补历史过程中首次尝试曾失败：`RPC failed; curl 56 OpenSSL SSL_read: unexpected eof`（大 pack 传输中断）。
**原因之一是此前设过 `pack.packSizeLimit=32m`，会把 pack 切成小块反而更容易断流**；清掉该配置并放宽 `http.postBuffer` / `lowSpeedTime` 后一次成功。

> **结论：做 fork 基座不要用 `--depth 1`。** 浅克隆省下的下载量，会在 push 阶段以更难诊断的方式还回来。

## 失败点 8：PowerShell 5.1 的脚本编码/解析陷阱（出现 3 次）

### 现象 A：中文脚本解析失败

```
The string is missing the terminator: ".
$(subexpression) is missing the closing ')'
```

### 根因 A

**PowerShell 5.1 读取无 BOM 的 UTF-8 `.ps1` 文件时按系统 ANSI 代码页（本机 GBK）解码**。
脚本里的中文注释/字符串被错误解码后，可能产生引号或括号字符，导致语法在解析期就崩。
典型表现：脚本**一行都没执行**，却报出一堆语法错误。

### 现象 B：here-string 未终止

```
The string is missing the terminator: '@.
```

根因同上（无 BOM 的 UTF-8 被按 GBK 解码，`@'`/`'@` 配对判定出错）。

### 现象 C：`Tee-Object` 写错目录

```
out-file : Could not find a part of the path '...\repo\logs\unshallow.log'
```

根因：管道重定向的目标路径**在管道执行前**按当时的工作目录解析；而脚本内的 `Set-Location` 会改变当前目录，导致路径解析到错误位置，整条管道未能执行。

### 修复（三条硬规则）

1. **给 5.1 的 `.ps1` 文件一律写纯 ASCII**（中文放 Markdown 文档里，脚本里不用中文）；
2. 脚本里避免 here-string，改为逐行 `Out-File` 或内联命令；
3. `Tee-Object` / `Out-File` **一律传绝对路径**，不要依赖工作目录。

## 失败点 9：token 被写进 `.git/config`（安全隐患，已清理）

### 现象

推送时用 `git push -u <带 token 的 URL> master:main` 成功，但 `-u` 会把该 URL 记录为分支上游：

```
[branch "master"]
	remote = https://x-access-token:gho_****@github.com/Whale-Talk/NGC-Nexus.git
```

token 以明文形式**落盘在 `.git/config`**。

### 根因

`-u`（`--set-upstream`）会把**实际使用的推送 URL**（含内嵌凭证）写进分支配置。
当为了绕开无法使用的 credential helper 而把 token 拼进 URL 时，就会连带落盘。

### 修复

```powershell
git config --unset-all 'branch.master.remote'
git config branch.master.remote origin
git config branch.master.merge refs/heads/main
```

清理后复查：`.git/config` 中 `x-access-token|gho_|ghp_` 命中数 = **0**，且 `git fetch origin` 正常、`git rev-list --count origin/main..HEAD` = **0**。

### 硬规则

1. **带 token 的 URL 只用于单次推送，绝不加 `-u`**；
2. 优先用原生凭证助手：`git config credential."https://github.com".helper '!gh auth git-credential'`（实测可用，无需 shell）；
3. 每次用完带 token 的命令后，**必须复查** `.git/config` 是否残留凭证。
