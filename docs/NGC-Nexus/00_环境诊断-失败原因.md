# NGC-Nexus 环境诊断：为什么前面几步"失败"

记录时间：2026-09-25　环境：Windows / DSH 会话（file policy = workspace-write）

本文件记录本次任务启动阶段出现的**全部失败点、根因与已验证的修复方式**。所有结论均为本机实测，非推测。

---

## 失败点 1：`git` 无法访问 GitHub（最核心）

### 现象

```
fatal: unable to access 'https://github.com/mavlink/qgroundcontrol.git/':
schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)
- 安全程序包没有可用的凭证
```

### 根因

Git for Windows 默认 TLS 后端是 **schannel**（调用 Windows SChannel/SSPI 接口）。
DSH 文件沙箱以非交互、受限令牌运行子进程，SChannel 在该令牌下拿不到可用凭证句柄，
于是**在发出任何 HTTP 请求之前就失败**——与网络、代理、GitHub 可达性完全无关。

### 证据（对照实验）

| 后端 | 命令 | 结果 |
|---|---|---|
| schannel（默认） | `git ls-remote https://github.com/mavlink/qgroundcontrol.git HEAD` | ❌ `SEC_E_NO_CREDENTIALS` |
| openssl | `git -c http.sslBackend=openssl ls-remote ... HEAD` | ✅ `25185047e8...	HEAD` |

### 修复

仓库级（**不动全局配置**）：

```powershell
git -C <repo> config http.sslBackend openssl
```

Git for Windows 自带 CA 包已确认存在：
`C:\Program Files\Git\mingw64\etc\ssl\certs\ca-bundle.crt`

代理已由既有全局配置提供：`http.proxy = http://127.0.0.1:7897`（本次未改动）。

## 失败点 2：写全局 `.gitconfig` 被拒

### 现象

```
error: could not lock config file C:/Users/Marx/.gitconfig: Permission denied
（Add-Content 同样报 Access to the path 'C:\Users\Marx\.gitconfig' is denied）
```

### 根因

当前 file policy 是 **workspace-write**：只允许写 `E:\04-Workspace_workbudy` 及其子目录。
`C:\Users\Marx\` 在工作区之外 → 写操作一律被沙箱拒绝。

### 修复

- 不写全局配置，改为**仓库级配置**（`git config --local`）或命令行 `-c` 一次性传入。
- 若确实需要改全局配置，需要把 file policy 提升到 `danger-full-access` 并逐条批准——本次未申请，
  因为仓库级配置已足够。

## 失败点 3：`pwsh` 命令不存在（后台任务 exit 1）

### 现象

```
pwsh : The term 'pwsh' is not recognized as the name of a cmdlet, function, script file, or operable program.
[status: completed, exit code: 1]
```

### 根因

本机只装了 **Windows PowerShell 5.1**，没有 PowerShell 7：

- `$PSVersionTable.PSVersion` = `5.1.26100.9444`，`PSEdition` = `Desktop`
- `Get-Command pwsh` → 空；`Get-Command powershell` → `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`

自动化外壳本身是用 5.1 启动的（工具名虽写作 `pwsh -Command`），所以在命令里再调 `pwsh` 必然找不到。

### 修复

用 5.1 兼容写法调用脚本，不要嵌套 `pwsh`：

```powershell
& '.\clone-qgc.ps1' *>&1 | Tee-Object -FilePath '.\logs\clone.log'
```

## 失败点 4（假故障，澄清）：`gh repo list` 表格是空的

### 现象

`gh repo list Whale-Talk --json ... | ConvertFrom-Json | Select-Object ... | Format-Table` 输出一张只有表头的空表。

### 根因

`gh` 侧**没有失败**：单独打印原始 JSON 可见 8 个仓库（oh-my-deepseek、causal-alpha-lab、
PX4-Autopilot-mjy、TEAMmanagementSYS、TencentDB-Agent-Memory、Nexus-Code、backtest-mcp、ClaudeCode）。
`gh api user` 亦正常返回 `login=Whale-Talk`。

问题出在我的 PowerShell 5.1 管道写法/显示层，把对象渲染丢了。

### 处理

不依赖 `Format-Table` 渲染，直接 `--jq` 让 `gh` 输出纯文本，或 `ConvertTo-Json` 复核。

## 一条环境级经验（建议写入长期记忆）

> 本机（沙箱内）执行 git 网络操作时，必须使用 `http.sslBackend=openssl`；
> 默认 schannel 必然报 `SEC_E_NO_CREDENTIALS`。
> 且本机只有 Windows PowerShell 5.1，脚本须用 5.1 兼容语法，勿调用 `pwsh`。
